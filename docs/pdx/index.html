PDX is a 2D game framework for PIPI. The compiler and VM remain untouched: PDX is an external native module with a stable PIPI import surface. It gives game code a frame loop, input, timing, drawing primitives, text, BMP sprites, atlas regions, camera transforms, WAV playback and collision/math helpers.

01 / Build and run

This release targets Windows x86-64 with MinGW-w64 g++, DirectX 9 development headers/import libraries and the DirectX 9 runtime. Build the language core, then build PDX separately. The PIPI compiler/VM source files and PIPIBC06 bytecode format are not changed by PDX.

:: Windows CMD, from the project root
build.bat
frameworks\PDX\build.bat
bin\pipi-vm.exe dist\PIPI_PDX_Demo.pbc

The native library is installed at modules/pdx/native/windows-x86_64/pipi_pdx.dll. Run the command from the project root so the built-in asset paths work. The demo is a playable arena: move with WASD or arrow keys, touch the orb to score, press ESC to exit.

Compatibility detail: PIPI v0.8.0 validates function calls during compilation. The Neon Arena example explicitly imports drawLine; missing imports now fail with a line-numbered diagnostic instead of a runtime unknown-function error. PIPIBC06 bytecode and Native Module ABI v1 remain compatible.

02 / The game loop

import { open as pdxOpen, pollEvents, beginFrame, endFrame,
  fillRect, drawText, keyDown, deltaTime, clamp,
  close as pdxClose } from "pdx";

let x = 120;
if (pdxOpen("My PIPI Game", 800, 600)) {
  while (pollEvents()) {
    let dt = clamp(deltaTime(), 0.001, 0.05);
    if (keyDown("LEFT")) { x = x - 220 * dt; }
    if (keyDown("RIGHT")) { x = x + 220 * dt; }
    if (beginFrame(16, 20, 34)) {
      fillRect(x, 240, 32, 32, 95, 220, 255);
      drawText("PIPI + PDX", 18, 16, 230, 240, 255, 18);
      endFrame();
    }
  }
  pdxClose();
}

Call pollEvents() before reading key edge events. Use deltaTime() for movement instead of moving a fixed number of pixels per frame. Clamp dt after a long pause so the first resumed frame does not teleport entities.

03 / Keyboard and mouse input

Held keys

keyDown("W") stays true while W is held. Multiple names can be combined using PIPI's ||.

if (keyDown("W") || keyDown("UP")) {
  playerY = playerY - speed * deltaTime();
}

Edge-triggered input

keyPressed fires once per down transition; keyReleased fires once on release. Mouse positions are client-area coordinates.

if (keyPressed("SPACE")) {
  // jump / attack / confirm
}
if (mousePressed("LEFT")) {
  // click action
}

Supported keys include A–Z, 0–9, arrows, SPACE, ESCAPE, ENTER, SHIFT, CTRL, ALT, TAB, BACKSPACE, DELETE, HOME, END, PAGEUP, PAGEDOWN, INSERT and F1–F12. Mouse buttons are LEFT, RIGHT and MIDDLE.

04 / Drawing and camera

All drawing belongs between a successful beginFrame(r,g,b) and endFrame(). Color channels are RGB integers clamped to 0–255.

World camera vs HUD

setCamera(playerX - 400, playerY - 300, 1.0);
fillRect(worldX, worldY, 32, 32, 90, 220, 255);

// Draw screen-space UI after resetting the camera.
resetCamera();
drawText("HEALTH: 100", 20, 16, 120, 255, 150, 18);

Camera mapping: screen = (world - cameraOrigin) * zoom. Zoom must be greater than 0 and no more than 16.

05 / Sprites, atlas and audio

Textures and sprite sheets

let atlas = loadTexture("frameworks/PDX/assets/pdx_atlas.bmp");
// Draw the second cell of a four-cell horizontal atlas.
drawTextureRegion(atlas, 120, 180, 64, 64, 0.25, 0.0, 0.25, 1.0);

PDX loads Windows BMP files from the process working directory. Magenta RGB (255, 0, 255) becomes transparent. `drawTextureRegion` uses normalized UV coordinates; an atlas with four equal columns uses UV width `0.25` per cell. Handles start at 1; free unused textures using `freeTexture(id)`. Max 64 textures and 4096×4096 each.

Run dist\PIPI_PDX_TextureDemo.pbc to see an interactive sprite sheet demonstration.

String-grid tilemaps

let atlas = loadTexture("frameworks/PDX/assets/pdx_atlas.bmp");
// 12 columns × 5 rows. 3 = wall, 2 = grass.
drawTilemap(atlas, "333333333333322222222223222222222223222222222223333333333333", 12, 5, 32, 80, 100, 1.25);

The map string is row-major, with exactly one character per cell. Tile IDs are hexadecimal 0–F; . or a space skips an empty cell. The atlas width and height must be divisible by the tile's source-pixel size. PDX 0.7 includes this low-level renderer; it is not a tilemap editor or chunk-streaming system.

Sound

playSound("assets/pickup.wav", false); // one-shot
playSound("assets/ambience.wav", true); // loop
stopSound();

Audio is simple asynchronous WAV playback through WinMM; there is no mixer or spatial audio in v0.8.0.

07 / Realistic limits

PDX 0.7 is a real starter game framework, not yet a complete game engine. It has a native window/render loop, input, timing, 2D primitive rendering, text, sprite textures/atlas slices, camera, audio playback and collision/math helpers.

It does not yet provide a scene graph, entity/component system, physics simulation, animation editor, tilemap editor/chunk streaming, PNG/JPEG decoding, a packaged asset pipeline or Linux backend. The PIPI language also has no first-class arrays/objects yet, which makes data-heavy entity systems awkward in pure PIPI. Those can be added as external libraries/modules while leaving the compiler and VM unchanged.

Security: PDX is native code. A plugin runs with the same OS privileges as PIPI; the native ABI is a compatibility contract, not a sandbox.
