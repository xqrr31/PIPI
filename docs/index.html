PIPI is a general-purpose language with a C89 compiler, its own bytecode and VM, and a versioned native-module ABI. Build a graphics framework, audio engine, database driver, HTTP stack or platform API as a separate module — the core compiler and VM stay untouched.

01 / Quick start

Linux: GCC/Clang and X11 development files for the legacy GUI bridge. Windows: MinGW-w64. No Java or Python is needed to compile and run PIPI programs.

# Linux / POSIX shell
./build.sh
bin/pipi-c compile examples/native_module.pipi -o dist/NativeDemo.pbc
bin/pipi-vm dist/NativeDemo.pbc

# Windows CMD
build.bat
bin\pipi-c.exe compile examples\native_module.pipi -o dist\NativeDemo.pbc
bin\pipi-vm.exe dist\NativeDemo.pbc

The default build compiles a sample third-party native extension and exercises a native-to-PIPI callback. Native modules are looked up using PIPI_MODULE_PATH.

02 / General-purpose syntax

The v1.0 language subset supports variables, optional type annotations, functions, parameters, return values, arithmetic, comparisons, assignments, branches, loops and module aliases.

import { print } from "pipi/core";
import { clamp as limit, greet } from "pipi/extra";

fn adjust(score: number) {
  if (score > 10) { return limit(score, 0, 10); }
  return score;
}

let score: number = 27;
print(greet("bestie"));
print("normalised = " + adjust(score));
let / const / varfn / returnif / elsewhile+ - * / %comparisonsimport aliases

This is not full TypeScript yet: static type enforcement, arrays/objects, loops beyond while, closures and source-body package modules remain future work. The new native-module path supports third-party executable libraries today.

03 / Native modules: the extension contract

Each module has a logical import name, a `.pmod` manifest, and one platform shared library. The compiler checks exports and emits a qualified target, so `open` from one package won't collide with `open` from another.

# lib/pipi/extra.pmod (also shipped with its package)
PIPI-MODULE 1
name pipi/extra
kind native-plugin
abi 1
exports clamp greet version callCallback

Each shared library exports the same entry symbol:

const PipiNativeModuleV1 *pipi_native_module_v1(void);

The descriptor supplies the ABI version, module identity, supported-function check, initializer, call dispatcher and shutdown hook. `include/pipi_native.h` is the public C89-compatible header. Function calls exchange `null`, `number`, `string`, `boolean` and named PIPI function values; the host API can invoke PIPI callbacks.

Install a module without editing PIPI core

pipi-modules/ └── your-module/ ├── your-module.pmod └── native/ ├── windows-x86_64/pipi_your-module.dll └── linux-x86_64/libpipi_your-module.so

Set PIPI_MODULE_PATH to the directory containing the module packages. For a project-style root with a modules/ directory, the loader also searches modules/<name>/native/<platform>/. Compiler manifest search supports PIPI_LIB_PATH and PIPI_MODULE_PATH.

# Linux
export PIPI_MODULE_PATH="$HOME/pipi-modules"
./bin/pipi-c compile app.pipi -o app.pbc
./bin/pipi-vm app.pbc

# Windows CMD
set PIPI_MODULE_PATH=C:\dev\pipi-modules
bin\pipi-c.exe compile app.pipi -o app.pbc
bin\pipi-vm.exe app.pbc

Wide range of domains

The ABI is domain-agnostic. Framework authors can expose graphics, DirectX/OpenGL/Vulkan, audio/MIDI, keyboard/controller input, networking and HTTP, database drivers, image/audio codecs, compression, cryptography, physics, filesystem, OS APIs, hardware sensors, ML runtimes and specialized tools. Platforms can ship distinct implementations while PIPI imports one logical module name.

Security: native code runs with the same permissions as PIPI. The ABI validates version and module identity; it is not a sandbox. Only load modules you trust.

04 / PDX 0.8.0 — 2D game framework

PDX has grown from a Direct3D 9 drawing proof into an external 2D game framework for PIPI. It adds a frame loop, delta-time timing, FPS pacing, keyboard/mouse input, 2D rectangles/lines/circles, cached text, BMP sprites, sprite-sheet regions and row-major string-grid tilemaps, camera transforms, WAV playback, AABB collision and math helpers. All of that lives in the external native DLL; the PIPI compiler, VM, bytecode and public module ABI remain unchanged.

import { open as pdxOpen, pollEvents, beginFrame, endFrame,
  fillRect, drawText, keyDown, deltaTime, clamp,
  close as pdxClose } from "pdx";

let x = 120;
if (pdxOpen("My PIPI Game", 800, 600)) {
  while (pollEvents()) {
    let dt = clamp(deltaTime(), 0.001, 0.05);
    if (keyDown("LEFT")) { x = x - 220 * dt; }
    if (keyDown("RIGHT")) { x = x + 220 * dt; }
    if (beginFrame(16, 20, 34)) {
      fillRect(x, 240, 32, 32, 95, 220, 255);
      drawText("PIPI + PDX", 18, 16, 230, 240, 255, 18);
      endFrame();
    }
  }
  pdxClose();
}

Build the external backend from Windows with MinGW-w64, DirectX 9 headers/import library and WinMM:

frameworks\PDX\build.bat
bin\pipi-vm.exe dist\PIPI_PDX_Demo.pbc

Open the full PDX game-framework documentation → for all functions, parameter signatures, sprite atlas guide, audio, input and practical limitations.

PDX remains an external 0.8.0 framework while the overall PIPI distribution is now v1.0.0. This release adds the C89 standard-library modules and PIPIwood packages without changing the bytecode or native ABI. The Windows DirectX DLL still requires a Windows build for runtime graphics testing.

05 / PIPIBC06

New compiler output starts with the 8-byte magic PIPIBC06. The container keeps the v0.5 layout; the VM also accepts PIPIBC05 files. Native module targets are constants, so no framework-specific bytecode opcode is needed.

ValuePUSH_NUM, PUSH_STR, PUSH_BOOL, PUSH_NULLPush constants
VariablesLOAD, STORE, DECLARERead/write runtime variables
MathADD, SUB, MUL, DIV, MODArithmetic and string concatenation
